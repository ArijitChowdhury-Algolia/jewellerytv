## Quality and operating limits

The application and tracked tests pass local lint, dependency validation, TypeScript and build checks. The prior production launcher incorrectly used a development-only health flag and hid the Concierge. The launcher no longer gates on environment or health; the server alone rejects chat when its selected published agent ID is missing or invalid. The strict Agent Studio tool now requires `sourceQuote` as a string or null. The browser callback keeps an exact per-fact phrase when supplied; null uses the exact current short shopper message, while long messages fail closed. The final staged-tree test counts and hosted UI outcome belong in the private Plan 3.1 and `SESSION.md` handoff. Repository `format:check` remains red: 59 files need formatting, and `check:line-policy` reports nine handwritten modules over 500 lines without recorded exceptions. These are open engineering debts, not passes. Full live-agent acceptance, cost, latency and classifier behavior are not proven. Very large input-token use was observed in Agent Studio conversations. The general search proxy still forces analytics and clickAnalytics off; this needs a separate measurement decision. The app has no checkout, login or cross-device persistence. Saved/Compare session lifecycle is intentionally deferred until the core flow stabilizes.

The previous 4 KB turn-context cap was application code, not a verified SDK limit. It was removed; per-value and key-count bounds remain. Product and blog sources stay fixed and read-only. The older architecture-comparison runs are preserved as history, not an active test harness.
